# vis comic — комиксы через kie.ai

Расширение нашего `vis`: сценарий в JSON → кадры одной моделью → пузыри кодом →
готовая страница `page.jpg`. Кадр в 1K стоит ~8 кр ≈ $0.04, комикс на 4 кадра —
~32 кр ≈ $0.16. Реплики, подписи и пересборка страницы — 0 кредитов.

## Железные правила

1. **Сценарий пишешь ты, по словам хозяина.** Он говорит «комикс про кота и
   дедлайн, 4 кадра» — ты раскладываешь на сцены, реплики и подписи. Шаблон:
   `vis comic --example`. Покажи хозяину текст сценария ДО генерации.
2. **Сначала `--dry-run`, потом деньги.** Назови цену комикса целиком. Дороже
   $0.20 или хозяин не сказал число кадров — спроси.
3. **Реплики ТОЛЬКО в сценарии, никогда в промпте сцены.** В scene описывается
   картинка без слов; текст в кадре рисует код. Запрет надписей уже вшит в
   промпт — не убирай его.
4. **Постоянный герой = референс.** Если героев больше нуля и комикс длиннее
   2 кадров: сначала сгенерь персонажа (`vis crea "портрет героя, нейтральный
   фон, в полный рост" --models nano-banana-2 --format square`), дай хозяину
   выбрать кадр, положи путь в `characters[].ref`. Без референса герой может
   «плыть» от кадра к кадру.
5. **Правка текста — бесплатно.** Не та реплика, не тот якорь, не та раскладка —
   правь сценарий и `vis comic сценарий.json --assemble out/ПАПКА`. Перегенерация
   кадров для правки текста = выброшенные деньги.
6. **Посмотри на page.jpg глазами** (Read) до показа хозяину: пузыри не закрывают
   лица, текст читается, порядок реплик идёт слева направо и сверху вниз.
   Проблема с текстом — `--assemble`; проблема в самом кадре — только тогда
   перегенерируй (это новые деньги, скажи об этом).
7. **Бюджет — предохранитель в коде**, не обходи его без явного «да» хозяина.

## Порядок работы

```bash
vis comic --example > сценарий.json   # шаблон
# ...правишь сценарий под задачу...
vis comic сценарий.json --dry-run     # план и цена, бесплатно
vis comic сценарий.json               # генерация + пузыри + страница
vis comic сценарий.json --assemble out/2026-…_название   # правка текста, 0 кр
```

Результат: `out/…/page.jpg` — страница; `panels/` — чистые кадры без текста;
`bubbled/` — кадры с репликами; `scenario.json` — копия сценария (паспорт).

## Формат сценария

```json
{
  "title": "Кот и дедлайн",            // заголовок страницы
  "style": "цветной комикс, чистые толстые контуры, плоские цвета",
  "format": "square",                   // формат кадра: square|post|portrait|…
  "layout": "grid",                     // grid (2 колонки) | strip (лента) | wide (ряд)
  "seed": 7,                            // один seed на серию, если модель умеет
  "characters": [
    { "name": "Кот", "desc": "упитанный рыжий кот в синем галстуке", "ref": "refs/kot.jpg" }
  ],
  "panels": [
    {
      "scene": "Кот сидит за столом с ноутбуком",     // картинка БЕЗ слов
      "cast": ["Кот"],                                 // кто в кадре (нет — все)
      "caption": "Понедельник, 9:00",                  // авторская подпись
      "captionAt": "top-left",
      "bubbles": [
        { "who": "Кот", "text": "Успею. Времени вагон.",
          "type": "speech", "at": "top-right", "tail": "down-left" }
      ]
    }
  ]
}
```

Пузыри: `type` — speech (эллипс) | thought (мысль с пузырьками) | shout
(звезда крика; с `tail: "none"` — это звук/SFX: «БАМ», «ВЖУХ») | caption
(прямоугольная подпись; `captionFill: "#ffffff"` — белая, как в журнальных
комиксах). `at` — якорь: top-left, top, top-right, left, center, right,
bottom-left, bottom, bottom-right или `{x,y}` в долях кадра. `width` — доля
ширины кадра под текст (уменьшай для мелких SFX). `tail` — куда смотрит хвост
(к говорящему): down-left, down, right… или none. `who` — только для
читаемости сценария, не рисуется. У кадра может быть свой `format` (см. ниже).

## Журнальная страница (layout "page") — как в настоящих комиксах

`layout: "page"` — вёрстка настоящей комикс-страницы: первый кадр — широкий
«крючок» на всю ширину, середина — ряды по 2–3 кадра, последний — широкий
финал. Первому и последнему кадру ставь `"format": "landscape"` (3:2),
середине — square (по умолчанию). Многостраничная история — отдельный сценарий
на каждую страницу, у 2-й и дальше `"showTitle": false`.

Правила ремесла (из практики Marvel и учебников по комикс-вёрстке):
- **Крупный кадр = медленный, важный момент; мелкие = быстрые действия.**
  Открывающий кадр задаёт место (establishing shot), финальный — клиффхэнгер
  или пэйофф; первый, центральный и последний кадры страницы главные.
- **4–6 кадров на страницу.** Больше — только для быстрой болтовни.
- **Взгляд ведёт Z-путь**: читатель идёт слева направо, сверху вниз; первый
  говорящий — левее и выше. Хвост пузыря — ко рту говорящего, SFX — к источнику
  звука, реплика героя — над его головой, а не над чужой.
- **Подписи-нарратив** (время, место, внутренний голос) — белые прямоугольники
  по углам, они читаются ПЕРЕД пузырями, если стоят выше.
- **Страница кончается вопросом**: последний кадр каждой страницы должен
  заставить открыть следующую.

Вёрстка (владелец забраковал ровную сетку «Ночной смены» — равные квадраты
ЗАПРЕЩЕНЫ; уточнено его референсами Хранителей/Марвела 10.08.2026):
- **База — сетка 3×3 со слияниями** (метод Хранителей): страница = три ряда по
  три колонки, кадры получаются слиянием соседних клеток (широкий = 3 колонки,
  средний = 2, узкий = 1; высокий = 2 ряда). Сотни узоров — у КАЖДОЙ страницы
  истории свой узор, не повторять один макет 1:1.
- **Каждый кадр в чёткой чёрной рамке**, между кадрами и по краям страницы
  ровные белые поля одинаковой толщины. Кадры навылет (bleed) и рваные рамки
  владельцу НЕ зашли — не использовать. Врезки/скосы — редко и аккуратно.
- **Рамки ТОНКИЕ, поля УЗКИЕ** (~1.5% ширины страницы): толстые рамки владелец
  забраковал. 6–7 кадров на страницу, кадры сопоставимых размеров, сюжет
  маленькими плавными шагами (промежуточные биты, не скачки). Леттеринг —
  единый округлый комикс-шрифт на всей истории (строку про шрифт — в каждый
  промпт). frame.cjs жмёт поле 16px.
- **Центр страницы — якорь**: самый важный кадр держит середину; крупный кадр =
  медленный важный момент, узкие кадры = быстрые биты.
- Режим одностраничной генерации (модель рисует вёрстку и пузыри сама, победитель
  владельца — GPT Image 2, ~3 цента/стр в 2:3): в промпт ОБЯЗАТЕЛЬНО класть
  строки про рамки/ровные поля и про анатомию («кисти прорисованы, ровно пять
  пальцев, конечности правильной формы»), сюжет расписывать по рядам сетки.
  Референсы: лист героев + первая страница истории (стиль). Готовую страницу
  прогнать через continuation/frame.cjs (выравнивает поля бесплатно).
  Минус режима: правка текста = перегенерация кадра.
  ЧЁТКОСТЬ: по умолчанию `--resolution 2K` (заказ владельца, 10 кр ≈ 5 центов
  за страницу gpt-image-2) — в 1K плывут пальцы и мелкие лица. 4K — для печати.

## Как раскладывать реплики

- Первый говорящий — выше и левее: читают слева направо, сверху вниз.
- 1–2 пузыря на кадр, реплика до ~8 слов. Длиннее — дели на кадры.
- Переносы строк можно задать самому: `"text": "Успею.|Времени вагон."`.
- Хвост должен смотреть на говорящего, не в пустоту; думает — thought, орёт — shout.
- Подпись (caption) — для времени и места, не для реплик.
- scene пиши как кадр фильма: кто где, что делает, свет, ракурс. Слова «комикс,
  стиль» не повторяй — style добавляется ко всем кадрам сам.

## Грабли

- Кадры идут параллельно; упавший кадр не валит комикс — на странице будет
  заглушка. kie.ai списывает кредиты при создании задачи, поэтому после падений:
  `vis reconcile`, потом `vis fetch <taskId>` (бесплатно), файл в `panels/NN.jpg`
  и `--assemble`.
- Модель по умолчанию nano-banana-2 (лучше всех держит героя по референсу
  из дешёвых). Цена у неё «(оценка)» — сверяй `vis credits` после прогона.
- Слишком длинная реплика раздувает пузырь на полкадра — режь текст, а не шрифт.
- `strip` — лента для Telegram (1080 шириной), `grid` — классическая страница,
  `wide` — все кадры в ряд (обложка).
